# MC 门店自助终端 · 自助收银需求

**适用设备** 27 寸 Android 触屏终端，竖屏 1080 × 1920。

**原型入口** 打开预览后，点击右上角「自助收银」。[GitHub Pages 预览](https://mc-mall.github.io/demo-preview/android-kiosk-prototype/)

## 1. 业务流程

顾客可只买校服、只买实物或将两类商品一起结账。校服从学校目录选购，实物在第二步扫码。顾客在扫码页选择取货方式，再以会员或非会员身份结账。支付完成后打印双联小票，店员按所选方式交付商品。

## 2. 选校服和加入购物车

- 首页左侧为学校分类，右侧为当前学校、学段和商品，宽度按 **1:2** 排布。商品卡片每行两列。放大学校名称、校徽和商品主图，缩小主图与卡片边缘的留白。窄屏时学校分类放到商品区上方。
- 切换学校时默认进入该校第一个学段。切换学段时只展示该学段的商品。原型学校为培华中学、澳坊中学、广大学校。
- 商品卡片展示主图、名称、颜色、MOP 单价及「选尺码」。商品详情提供尺码选项与尺码表，数量初始为 1，修改数量时更新小计。选定有效尺码后方可加入购物车。
- 同一商品的同一尺码合并计数，不同尺码分别列项。切换学校或学段时保留已选商品。
- 首页购物车栏显示总件数和金额。「查看已选」可加减数量或移除整行，减到 0 件时移除该行，件数和金额同步更新。

## 3. 扫实物和确认结账

- 扫描已登记的非校服商品条形码后加 1 件，重复扫描累加，并提示商品名和当前数量。扫到校服条码时提示返回学校分类选购。空码和未知码显示错误，购物车保持原值。
- 购物车按校服与实物商品分组，支持加减数量。结账明细分别显示两类商品小计，应付金额为各商品单价乘数量后求和，统一以 MOP 显示。
- 顾客可从扫码页返回选校服，购物车保留。购物车为空时，会员和非会员结账按钮均不可用。
- 顾客在未完成的购物中切换模式或重置演示，有商品或订单时需先确认清空。支付处理中或待确认时锁定模式切换和重置。

### 取货方式

| 方式 | 结账前 | 付款后 |
| --- | --- | --- |
| 店内自提 | 默认选中，可直接结账 | 店员拣齐校服后通知顾客到店内取货台领取。已扫码实物随身带走，纯实物单无需等待拣货 |
| 暂存智能柜 | 选中后可直接结账 | 已扫码实物随单交给店员。收到存柜通知后，顾客可自行安排时间回店，凭客户联条码开柜 |
| 窝蜂配送 | 弹窗选择并确认自提站点，再结账。取消弹窗保留上次已确认的选择 | 店员将订单商品交窝蜂配送。到站后，顾客自行安排时间到所选站点取货 |

付款页和两联小票均显示取货方式。窝蜂订单同时显示自提站点。当前使用明确标注的示例站点。

### 会员与非会员结账

| 结账方式 | 规则 |
| --- | --- |
| 非会员 | 点击「非会员结账」后直接选择支付方式。 |
| 已注册会员 | 选择区号并输入手机号。查到会员时显示姓名、等级和脱敏手机号，顾客确认后选择支付方式。 |
| 新会员 | 查不到时显示待注册的完整号码，由顾客再次确认。确认后注册为普通会员并继续支付。返回修改或关闭弹窗时不注册。 |

手机号默认选澳门 `+853`，澳门和香港 `+852` 均为 8 位。中国内地 `+86` 为 11 位且以 1 开头。粘贴带受支持区号的号码时自动切换区号。号码格式错误时提示修改。

## 4. 付款和异常处理

可选支付方式为 **Mpay、中银智慧付、Alipay HK**。选择方式后，终端等待扫描顾客付款码，并展示订单号、商品件数和订单总金额。付款码被识别后进入「等待支付结果」。

| 支付状态 | 顾客操作与订单规则 |
| --- | --- |
| 待付款 | 可更换支付方式。首次付款前可返回购物车修改，重新结账时按当前购物车生成订单。 |
| 支付处理中 | 等待模拟回调，暂不能再次付款。 |
| 支付失败 | 保留订单号和金额，可在同一订单上重新付款或更换支付方式。 |
| 支付结果待确认 | 保留订单号和金额，只能查询原订单。若结果尚未就绪，提示稍后再查。 |
| 支付完成 | 显示实付金额、方式、件数和六位取货号，生成双联小票并调起浏览器打印。 |

已扫付款码的订单和支付状态可在同一标签页刷新后恢复。付款码本身不保存。支付确认前不生成取货号、不打印小票。

## 5. 双联小票与取货

| 小票 | 内容和用途 |
| --- | --- |
| 客户联 | 六位取货号及对应的 Code 128 条码、取货方式和站点、付款时间、全部商品明细、支付方式及实付金额。暂存智能柜订单印有扫码开柜指引。 |
| 仓库联 | 与客户联共用取货号，显示取货方式及站点。有待交付商品时打印 Code 128 条码，并列出 SKU、规格、数量和货位或现场交接说明。店内自提的纯实物单显示「无需拣货」。 |

两联按 80 mm 小票版式分别出页。顾客可在「支付完成」页补打，也可点击「开始下一单」，使用空购物车继续选购。

1. 店员进入「仓库拣货」，按仓库联配货。完成现场备货、存柜或配送交接后，扫描仓库联条码或输入六位取货号确认。重复确认会返回当前状态。
2. 店内自提和暂存智能柜确认后即可取货。窝蜂交接后显示「已交窝蜂配送」，在「窝蜂配送中」点击「模拟站点到货」后才显示「已到站，可以取货」。
3. 顾客从「查询取货进度」输入六位取货号，查看所选方式、站点和当前状态。查不到时提示核对客户联。
4. 店员在「仓库拣货」确认暂存智能柜订单后，原型分配空置柜位，顾客端显示「已存入智能柜，可以取货」。没有空柜时保留待存柜状态。升级前已模拟存柜但没有柜位的订单，需在仓库重新确认一次。
5. 顾客进入「自提柜 → 取货」，扫描客户联条码或输入六位取货号，打开对应柜门。确认完成后释放柜位，取货进度显示「已在智能柜取货」。未存柜、已取货、店内自提和窝蜂配送的订单扫码时会给出相应提示。

## 6. 原型验收

以下用例使用页面内的演示入口，手机号使用演示号码或测试号码。

| 用例 | 关键操作 | 预期结果 |
| --- | --- | --- |
| 竖屏布局 | 以 1080 × 1920 打开，选择广大学校 | 左右区宽度为 1:2，商品两列，三件商品与购物车栏可在首屏完整看到 |
| 校服加购 | 同款分别选两个尺码，再重复添加一个尺码 | 购物车按尺码分行，同尺码累加，可在「查看已选」修改或移除 |
| 实物扫码 | 进入「扫实物」，连续点两次「运动袜」，再提交未知码 | 袜子为 2 件，未知码报错且金额不变 |
| 店内自提 | 加入校服和实物，以非会员结账并模拟支付 | 两类商品同一笔付款，客户联含全部商品，仓库联仅含校服 |
| 客户联条码 | 在付款成功页打开双联打印预览，识读客户联条码 | 读出的六位数字与客户联取货号一致，保留开头的零 |
| 暂存智能柜 | 完成支付后先扫码一次，再在仓库点击「模拟存柜」，最后到自提柜扫描客户联 | 存柜前无法开门。存柜后打开该单对应柜门，取货完成后无法用同一条码再次开柜 |
| 智能柜满柜 | 满柜时确认存柜，释放一个柜位后重试 | 满柜时保持待存柜，重试后分配空置柜位 |
| 窝蜂配送 | 选站后取消，再确认一个站点并支付。依次模拟交接和到站 | 取消保留原选择，两联显示确认的站点，交接后待到站，到站后才可取货 |
| 会员结账 | 使用「填入演示手机号 00000001」查询并确认 | 显示会员资料，确认后进入支付方式选择 |
| 新会员确认 | 用未注册测试号查询，先返回修改，再查询并确认注册 | 返回时未注册，明确确认后才注册为普通会员并继续付款 |
| 支付失败重试 | 点「模拟支付失败」，再重新付款或更换方式 | 订单号与金额保持一致，重新付款成功后才生成小票 |
| 回调延迟 | 点「模拟回调延迟」，刷新当前标签页并查询 | 恢复同一订单，结果未就绪时可稍后重查，确认成功后只生成同一个取货号 |
| 拣货和查询 | 记录混合订单取货号，在另一同源标签页进入「仓库拣货」并模拟扫码 | 顾客页更新为「拣货完成，可以取货」，重复扫码提示已通知 |
| 店内自提只买实物 | 不选校服，扫入实物并选择店内自提付款 | 小票可打印，订单不进入待拣队列，取货查询显示「无需等待拣货」 |

## 7. 真机联调范围

当前为静态 H5 演示。商品、价格、尺码、货位、会员查询和支付结果使用演示数据。会员注册和拣货记录保存在浏览器，拣货通知通过同一浏览器、同源页面状态同步展示。

上线前需联调正式商品条码、价格与货位，会员查询与注册接口，支付回调及主动查单，智能柜存取与取货凭证，窝蜂站点和配送状态，以及取货通知渠道。在 27 寸真机和 80 mm 热敏打印机上验收触控、扫码回车、打印及条码识读。

原型实现参见 [商品与样本数据](catalog.js)、[购物车与支付](checkout.js)、[会员](membership.js)、[拣货与取货进度](pickup.js)、[自提柜](app.js)、[竖屏与小票样式](checkout.css)。
